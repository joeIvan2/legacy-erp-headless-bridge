H LEGACY ERP → AI
方向鍵／空白鍵換頁

01 · 要解決的問題

資料都在 ERP 裡，
卻沒有一扇門。

這套 26 年前的 32-bit Delphi ERP 沒有現代 API，也沒有 CLI。人看得到、點得到；但外部系統無法安全、穩定地呼叫。

Windows-only No API No CLI 商業規則不能丟

問題不是 ERP 太舊，而是所有新需求都被卡在「只能由人操作畫面」。

02 · 商業代價

沒有接口，六個成長需求一起被卡住。

電子發票

品項、稅別、金額要正確，還要留下可查的處理結果。

第三方支付

付款、Webhook 與 ERP 單據之間，需要可靠對帳。

第三方貨運

標籤、追蹤、代收，只能取得完成任務所需的資料。

業務異地打單

手機、Mac、Discord 能下單，不等於遠端控制公司電腦。

銷售預測

歷史交易應該變成補貨、回購與交叉推薦訊號。

Lead 追蹤與預測

誰該先跟進、下一步做什麼、結果如何，都要能回到閉環。

不是沒有資料；是資料出不來，外部結果也回不去。

03 · 解題策略

不重寫 ERP。先選對入口。

先用反編譯、DFM 與型別研究看懂邊界；再依模組成熟度，選擇其中一條路。

路線 A

Accessibility + SQL
雙重驗證

還沒找到穩定 Kernel 時，用 UI 物件名稱與唯讀資料查詢，核對同一張單。

  1. Live Inspect 讀 UIA 物件
  2. 唯讀 SQL 查持久化資料
  3. 兩邊一致才納入流程
OR
路線 B

直接接 ERP Kernel
保留商業規則

已找到穩定商業物件時，跳過座標、滑鼠與鍵盤，直接走既有規則。

  1. 固定輸入欄位
  2. 既有商業物件執行
  3. 完成後獨立核對
兩條路最後都收斂成 Headless CLI + 可驗證 JSON

04 · 路線 A

畫面一把尺、SQL 一把尺。
量的是同一張單。

UI 看到的值=SQL 查到的值→欄位關係成立

05 · 路線 B

找到 Kernel，
就拿掉滑鼠和鍵盤。

正式流程不再靠視窗位置、焦點或人工節奏。查詢與建立都經固定命令邊界，結果再獨立核對。

UI 未觸碰 ERP 鍵盤事件 0 SQL 只讀核對
JSON 命令→ERP 商業物件→結果核對

06 · AI 工作流

當 ERP 有了 CLI，
業務可以在任何地方打單。

  1. 1
    自然語言業務說出要開什麼單
  2. 2
    固定欄位AI 只負責理解，不直接碰資料庫
  3. 3
    ERP 建單Kernel 執行原有商業規則
  4. 4
    SQL 驗證單號與內容核對後才回覆

07 · 企業整合

同一個接口，
接上外面的世界。

已落地
電子發票

整理品項、金額與處理結果

已落地
第三方貨運

建立託運、標籤、追蹤與代收

已落地
UDI／郵局版位

掃碼、紀錄與批次列印

已落地
第三方支付／應收

收款狀態、Webhook 與單據對帳

ERP 帳密與原廠元件仍留在受控 Windows 主機；外部服務只拿到完成任務所需的最少資料。後續擴充的是新供應商 Adapter，不必重做 ERP 整合。

08 · 從資料到決策

資料一旦能安全出來，
就能預測下一步。

橋接層負責「可信地拿資料」；分析層負責「下一個最佳行動」。兩邊分開，AI 才不會越權操作 ERP。

補貨預測誰可能快用完？
Lead 優先級今天先跟進誰？
交叉推薦下一個合理品項？
回寫閉環行動結果是否有效？

這不是把 Chatbot 放在舊流程旁邊。
是先看懂流程、補上接口，再讓 AI 可靠工作。
